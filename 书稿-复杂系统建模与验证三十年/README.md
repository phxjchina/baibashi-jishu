## 这本书想解决什么

1994 年，GoF 四人组写下 23 个设计模式的时候，软件工程界以为找到了银弹。三十年后回望，模型驱动的理念在方法论层面节节胜利，在工程落地层面却始终差最后一公里。

这本书想弄清楚的不是"模型驱动是什么"，而是三件事：

1. **三十年里，什么真的变了？** 从系统工程的纸面草图到今天的可验证世界模型，哪些是概念演进的必然，哪些是换汤不换药。
2. **为什么每次落地都卡在同一处？** 从 MDA 到 MBSE 到数字孪生，失败模式高度重复。重复意味着有结构性原因。
3. **出路的形状是什么？** 走向"可验证 AI"这条路，需要什么样的模型基础设施。

## 六层系统论：本书的框架骨架

| 层 | 名称 | 一句话 |
|----|------|--------|
| L0 | 元模型 | 模型背后的模型：什么需要被元层描述 |
| L1 | 结构模型 | 系统的形状：组件、连接、拓扑 |
| L2 | 行为模型 | 系统如何动：状态、事件、时序 |
| L3 | 定量模型 | 系统动得对不对：微分方程、约束、界限 |
| L4 | 不确定性模型 | 我们对模型本身有多确定：概率、区间、可信度 |
| L5 | 验证层 | 凭什么相信这个模型：证明、检查、对抗证据 |

### 五条世界模型构造路线

| 路线 | 核心思路 | 难度 |
|------|---------|------|
| 纯学习式 | 从交互数据中直接学出隐空间动力学 | 高（不可解释、不可验证） |
| 混合符号-神经 | 神经感知 + 符号约束 | 中高 |
| 物理先验注入 | 把守恒律、结构对称性写进损失 | 中 |
| 结构化生成 | 用图/语法约束生成空间 | 中 |
| 验证导向 | 先写规格，再设计满足规格的模型 | 最高 |

> 详细论证见书稿正文，此处仅列骨架。

# 验证实战：知识存量非负与有界增长的模型检验

前面两篇分别用 TLA+ 立宪、用 Coq 证铁律。这篇做**验证实战**：拿一个具体性质——"知识存量非负"且"有界增长"——跑成一次真正的模型检验，并接上主线4-12 那个能跑的 Python 最小系统。按 C 档，只给直觉和可读规格。

## 一、名-实对应

- **模型检验（model checking）**：自动穷举一个（有限）系统的所有可能状态，检查某性质是否全程成立。TLC 就是干这个的——它不抽样，它把状态空间走一遍。
- **有界增长（bounded growth）**：某个量不会无限膨胀，因为有资源或容量上限。它对应"稳定公理"里的"有界"——系统被推，要回得来，也不能飞出去。

## 二、问题：能跑的模型，会不会乱套？

主线4-12 那个 Python 最小系统，代码能跑、世界能演进。但"跑起来"不等于"跑得稳"。比如：知识存量会不会越学越"负"？会不会无限膨胀把内存撑爆？

验证补的，正是这道"不乱跑"的保证。我们立两条宪法（不变式）：

- **不变式① 知识存量 ≥ 0**：不会越学越"负"（对应稳定/开放公理）；
- **不变式② 知识存量 ≤ 容量上限**：有界增长，不会无限膨胀（对应稳定/优化演化）。

## 三、规格（示意）

```
变量 存量 ∈ 0 .. 容量;          // 状态被显式限定在区间
初始: 存量 = 0;
下一步: 存量' = 存量 + 1         // 学习
    或  存量' = 存量 - 1;        // 遗忘（但有界，见不变式）
不变式: 存量 >= 0  ∧  存量 <= 容量;
```

TLC 穷举所有"学习/遗忘"的交错路径，自动确认：每一条轨迹都停在 `[0, 容量]` 区间里。

## 四、验证比测试强在哪

假设你手滑，把遗忘写成"`存量' = 存量 - 2` 当 `存量 = 0`"——

- **测试**：你可能恰好没抽到"连续两次在 0 处遗忘"这个用例，于是带着 bug 上线；
- **模型检验**：TLC 穷举时必撞上"存量变 -2"，立刻红叉反例，精确指出越界步。

一句话：**测试证"抽样没出错"，验证证"没有反例"。** 高风险系统（自动驾驶、医疗 AI）要的是后者。

## 五、三条主线在此汇合

- **主线4（代码）**：让世界**能跑**；
- **主线3（验证）**：让世界**不乱跑**；
- **主线2（骨架）**：让世界**有形状**（八公理/五机制）。

一个可验证世界模型 = 能跑 + 不乱跑 + 有形状。今天的大模型"能跑"已解决，"不乱跑"正是卡点。高承实说 AI 缺世界模型，我们补一句：**更缺的是"可验证的世界模型"。**

## 六、落点

模型检验把"验证"从论文变成可运行的护栏：你立不变式，机器穷举证没反例。下一篇进主线4-13，给我们那个 Python 最小系统真正加上"反馈与涨落"——让它能跑，也更像一个活系统。

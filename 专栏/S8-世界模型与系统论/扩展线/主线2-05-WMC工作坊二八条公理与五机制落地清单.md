# WMC 工作坊（二）：八条公理与五条机制的落地清单

上篇写了立论书和域覆盖规约——定"造什么、罩哪些地块"。这篇给你**施工验收表**：把魏氏八原理升格为"八条公理"（造模型时不可违反的前提），把五规律降为"五条机制"（让模型活的引擎）。每条都配一个能直接打勾的问句/提示。

## 一、名-实对应

- **公理（axiom）**：这里指"造模型时必须当前提守住、不许违反"的硬约束。它来自八原理，但语气从"原理如此"变成"你的模型必须如此"，否则不合格。
- **机制（mechanism）**：让模型真正"动起来、活起来"的五条演化引擎，来自五规律。原理是静态规矩，机制是动态实现。

一句话：**公理管"不准坏"，机制管"怎么活"。**

## 二、八条公理：逐条自检问句

| 公理（源自原理） | 自检问句（贴墙上，每次改模型问一遍） |
|---|---|
| 整体公理（整体性） | 删掉 30% 零件，功能是否断崖？若会，说明能力靠堆砌而非结构，不及格 |
| 层次公理（层次性） | 能否指出模型的 L0–L5 每一层输入输出？指不出，就是一锅粥 |
| 开放公理（开放性） | 断网 24 小时还准吗？不准，说明没真跟环境交换 |
| 目的公理（目的性） | 推它一下，它趋向某个状态吗？没有"吸引子"，就是无头苍蝇 |
| 突变公理（突变性） | 能否从"不会"突然"会"（跳变）？只能平滑滑动，缺了质变能力 |
| 稳定公理（稳定性） | 注入噪声，它收敛还是发散？发散就没有稳态盆地 |
| 自组织公理（自组织） | 不手调参数，结构自己长出吗？长不出，就是脚本不是系统 |
| 相似公理（相似性） | 换一个域，核心要重写吗？要重写，说明没通吃多域 |

这八问，就是你的"红线"。任何一次改动，若让某条公理答不上"是"，就别合并。

## 三、五条机制：逐条实现提示

| 机制（源自规律） | 实现提示（动手时往这方向做） |
|---|---|
| 结构功能机制 | 先定结构再定功能；要改功能，先动结构，别只调参数 |
| 信息反馈机制 | 加负反馈闭环：观测→算误差→修正。没有这环，模型不会"稳" |
| 竞争协同机制 | 让多个智能体既竞争又协同；只协同会僵死，只竞争会崩解 |
| 涨落有序机制 | 注入可控噪声，让秩序从扰动里自己长出来，而非全靠设计 |
| 优化演化机制 | 设一条"向上"的目标函数，让模型不止回放，还能演化 |

## 四、公理与机制的配合：一个例子

以"稳定公理 + 信息反馈机制"为例：

- 公理说"系统被推一下要回得来"——这是验收标准；
- 机制说"加负反馈闭环"——这是达成标准的具体做法；
- 两者合起来，你就有了一条**可验证**的要求：模型里必须存在"观测→误差→修正"的回路，且在该回路下对典型扰动收敛。

这就把一句哲学，变成了工程师能落地的活。

## 五、这份清单怎么用

1. 立论书写完，把本表贴在旁边；
2. 每加一个功能，过一遍八公理——有红线被碰，停下；
3. 每调一次架构，看五机制是否还转——卡住哪条，补哪条；
4. 进入验证章时，八公理要能写成"不变式"（见验证章上），五机制要能写成"仿真关系"（见验证章下）。

下一篇，我们正式进"验证章（上）"：为什么公理要翻译成"不变式"、规律要翻译成"仿真关系"——这是可验证世界模型的语法转换。

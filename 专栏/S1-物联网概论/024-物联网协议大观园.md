# 物联网协议大观园：一本真书里的"语种谱系"

## 一、我当年的困惑

MQTT 那篇发完，有同学留言："彭老师， MQTT 我懂了，可面试官还问我 CoAP、 LwM2M、 MQTT-SN，这几个跟 MQTT 什么关系？我是学了三个假协议吗？"

我当年比他还惨。我的知识图谱是这样的： MQTT 是一块， HTTP 是一块， CoAP 听说是一块， LoRa、 NB-IoT 不知道归哪块。脑子里像一锅八宝粥——**每样食材都认识，就是不知道谁跟谁是一锅的。**

后来还是付强那本书救了我。它第 2 章干了一件特别舒服的事：把物联网世界常用的协议，**按"站哪一层"给你码得整整齐齐。** 码完我恍然大悟：原来协议世界也分"普通话和方言"，还分"进门方式"和"进屋说话"。

这篇就按这个谱系讲。讲完你再看那些协议名词，全挂在树上了。

## 二、先立一个总框架：协议分两大家族

这是全文最要紧的一张图。协议世界，先分两大家族：

**第一家族：接入协议——管"怎么进互联网的大门"。**

LoRaWAN、 NB-IoT 归这里。它们是物理层/数据链路层的协议，解决的是：设备在荒郊野外的隧道里，怎么把数据弄到互联网上去。

注意一个细节：这一族的协议，**自己不在 IP 网络上跑**。 LoRa 是远距离低功耗无线技术，数据到了网关，才被翻译成 IP 世界里能跑的包（比如 MQTT）。

**第二家族：应用协议——管"进屋之后说什么话"。**

MQTT、 MQTT-SN、 CoAP、 LwM2M、 HTTP 归这里。它们假定数据已经能跑在 IP 网络上了，只管"用什么格式聊、怎么组织话题"。

我当年的粥锅，就是缺这个二分法。你记不住这些协议，多半也是因为把它们混成一锅了。**先问"它管进门还是管说话"，一半的困惑当场消失。**

## 三、应用协议家族，挨个白话

### MQTT：物联网的普通话

前座已详谈，这里只补三个硬知识。

第一， **出身贵族**。它是 1999 年 IBM 的 Andy Stanford-Clark 和 Arcom 的 Arlen Nipper 为一个"卫星连输油管道"的项目开发的——从娘胎里就带着"网络不可靠、设备低功耗"的基因。2010 年 IBM 公开 3.1 版本， 2014 年正式成为 OASIS 国际标准。

第二， **聊天模型是发布订阅**。设备不直接跟设备聊，都通过 Broker 这个"公告板"聊。发布者和订阅者互相不用认识——这叫解耦，是它能撑住百万设备的根本原因。

第三， **三种 QoS**：至多一次（发完就不管，像飞鸽传书）、至少一次（没回音就重发，可能重复）、只有一次（严格握手，绝不重不错）。选哪种，是可靠性跟开销的权衡，没有免费午餐。

### MQTT-SN：MQTT 的"传感器方言版"

MQTT 虽轻，但它跑在 TCP 上——要建长连接、要握手、要维持心跳。对一颗纽扣电池供电的传感器来说， TCP 这套礼数还是太重。

于是有了 MQTT-SN（Sensor Network 版）：**搬到 UDP 上，保留 MQTT 的订阅发布语义**，但不用维持那条昂贵的长连接。它引入一个" MQTT-SN 网关"角色——设备跟网关说方言，网关翻译成标准 MQTT 跟远端 Broker 通信。网关还支持自动发现，设备不用配地址，喊一嗓子就有人应。

一句话： **MQTT-SN = MQTT 减去 TCP 的负担，加上一个翻译。**

### CoAP：UDP 上的"弱化版 HTTP"

这个协议是我学生时代觉得最委屈的一个——明明长得像 HTTP，名气却小得多。

付强书里有句话说得极准：**"CoAP 是一个建立在 UDP 之上的弱化版的 HTTP 协议。"**

翻译成人话：

- HTTP 你怎么玩的？给个 URL，发个 GET/POST，服务器回你。CoAP 一样——设备可以用 `coap://192.168.1.150:5683/2ndfloor/temperature` 这样的地址， GET 拿温度、 PUT 改配置；
- 但 CoAP 的消息极小，**最小的数据包只有 4 个字节**，跑在 UDP 上，不维持连接；
- 它还偷学了 MQTT 一手： OBSERVE（观察）模式——设备说"我观察这个资源"，资源一变，服务器主动推给它。看，这就有订阅的意思了。

什么时候用它？付强在第 12 章开头那段"社区问答"特别真实：有开发者问"我的传感器资源很紧张，发布消息很慢，也要跑 MQTT 吗？"付强答：如果设备大部分时间只是往上报个数，养一条 TCP 长连接纯属多余——**用 CoAP，报完就睡。**

但注意他自己也提醒： NAT 网络下从服务器往回发 UDP 不可靠，所以 CoAP 只建议干"上报"这一件事，别指望它做控制。**没有银弹，只有取舍。**

### LwM2M：CoAP 之上的"设备管理规范"

LwM2M（轻量级 M2M）是 OMA 定义的协议，底层就用 CoAP 跑（可以跑在 UDP 上，甚至能跑在短信上），安全靠 DTLS。

它跟 CoAP 的分工是： CoAP 管"怎么把数据传对"， LwM2M 管"设备全生命周期怎么管"——开机怎么引导注册、怎么读设备型号固件版本、怎么远程配参数、怎么升级。

它的架构是三角： **LwM2M Bootstrap Server**（引导员，带设备注册）、**LwM2M Server**（管家，日常管理）、**LwM2M Client**（设备）。没有移动网络覆盖的偏远水电站，用短信做传输载体——这场景我讲课时常念：**技术方案从来长在场景里，不是长在 PPT 里。**

### HTTP/RESTful：老将出马

最后别忘了老将。在算力和电力都充沛的设备上（比如跑安卓系统的摄像头、工控机），**直接用 HTTP 就行**，跟在手机上开发 App 没区别， RESTful 接口一套，现成的 Web 生态全都能用。

设备还可以用 WebSocket 主动接收服务器数据——浏览器那套长连接，设备照样玩得转。

所以别笑 HTTP "老"。老将的价值是：**生态。** 你随手能拉起来的工程师、工具链、云服务，都是它的兵力。

## 四、接入协议家族：LoRaWAN 与 NB-IoT

回到第一家族。这两位解决的是"进门"的问题。

**LoRaWAN**： LoRa 联盟推的低功耗广域网协议。付强书里的场景我每次讲都鼓掌——**隧道施工的工程设备，在隧道深处几千米， 4G 和 Wi-Fi 覆盖不进去，设备还在移动，拉不了有线。** 怎么办？设备上装 LoRa 模块，数据经中继一跳一跳传出隧道口，交给能上互联网的 LoRa 网关，网关把数据封装成 IP 世界能跑的协议（比如 MQTT）发往云端。

**NB-IoT**：直接跑在蜂窝网络上（ GSM/LTE 都能部署），插物联网卡就能上网，不用 LoRaWAN 那样的网关转换。它的增益比传统基站高约 20 分贝——专业说法，白话就是：**别人钻不进去的地方，它能钻进去。** 地下车库、管道、地下室，都是它的地盘。

这两位和应用协议什么关系？**搭梯子和上楼的关系。** LoRaWAN/NB-IoT 负责把数据从荒野弄到云端门口， MQTT/CoAP 负责进门之后的事。很多商业平台的链路图，就是" NB-IoT 上来，转成 MQTT 进平台"。

## 五、一个真案例：会认人的交通探头（AI+IoT）

协议讲理论容易犯困，付强书第 5 章那个" AI+IoT "项目，把协议怎么用讲活了。

场景：一个交通探头，认出照片里的人和车，把识别结果实时送上平台，网页端实时看。

技术拼图是这样的：

- **端上**：安卓 App 用 TensorFlow Mobile 跑预先训练好的模型（付强特意说明：不用自己训练， Google 开源模型直接拿来推理）；
- **传输**：识别完的照片和结果，用 MQTT 发出去。

然后就撞上所有物联网工程师都会撞的墙：**图片是大文件，怎么用 MQTT 传？**

付强给了个漂亮的工程答案： **图片本身走云存储（七牛）， MQTT 只传图片的 URL。** 消息体最终长这样：

```json
{"id":"唯一消息ID","timestamp":1560250142,"image_url":"https://...jpg","objects":["person","car"]}
```

为什么这么设计？书里列了四条理由，条条实在：订阅端可以按需下载；能传超过 256MB 的文件（ MQTT 单包上限约 256MB）；省 Broker 的带宽；省 Broker 的存储。

还有个细节特别见功力： **消息去重**。MQTT 的 QoS 1 可能重复投递，所以每条消息带个唯一 ID（ UUID ），订阅端拿个小本本记下收过哪些 ID，重复的扔掉。

你看，一个"探头认人"的小项目，把协议选型、大文件传输、 QoS 权衡、去重，全串了一遍。**这就是协议大观园的正确打开方式：不是背参数，是看它们怎么打配合。**

## 六、一点"为什么这么想"的思考

协议学到这儿，我最大的感悟反而跟技术无关：

**从来没有什么"最好的协议"，只有"最合适的场景"。**

低功耗小数据上报？ CoAP/MQTT-SN。海量设备双向控制？ MQTT。资源充沛的安卓设备？ HTTP 直接上。偏远无网？ LoRaWAN/NB-IoT 先进门。要管设备全生命周期？ LwM2M 那套规范现成。

这跟选交通工具一个理：上班三公里，电动车比跑车快；跨省搬家，跑车不如火车。**脱离场景谈技术优劣，都是耍流氓。**

那怎么才能"看场景选协议"？我的笨办法，也是真办法：**把每个协议"出生时为了治什么病"记住。** MQTT 治的是"卫星链路不稳定还要传数据"， CoAP 治的是"设备太省连 TCP 都跑不动"， LoRa 治的是"郊区没信号"。**病记住了，药方自然不会开错。**

下一篇讲物业公司里最容易被忽视、却最见架构功力的一环： **Broker 怎么"主动给后端打电话"—— Webhook 和 Hook 机制。** 一个只会轮询的后端，和一个会等回调的后端，差的不是几行代码，是整整一个段位。

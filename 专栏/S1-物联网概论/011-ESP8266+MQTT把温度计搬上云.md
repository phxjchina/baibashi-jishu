# ESP8266 + MQTT：把温度计搬上云，手机随时看

## 一、场景：人在宿舍，想知道实验室几度

上一篇的门禁，数据还困在板子上。这篇解决另一个挠头事：

我想知道实验室多少度，人却躺在床上。怎么办？

思路：让实验室的板子自己测温、自己上网、自己把数据"喊"到云上，我躺床上用手机"听"就行。

听着简单，这里头有个关键问题：板子在实验室，手机在宿舍，两边谁也不认识谁，怎么对上话？答案就是这节的标题——**MQTT**。

## 二、材料清单

| 零件 | 干啥用 | 备注 |
| --- | --- | --- |
| NodeMCU（ESP8266 开发板） | 大脑 + 神经 | 带 WiFi，二三十块 |
| DHT11 温湿度模块 | 眼睛 | 最土的温湿度传感器 |
| USB 线 + 手机 | 看数据 | 手机装个 MQTT 调试 App |

## 三、原理：MQTT 就是个"快递柜"

MQTT 这个词，很多教程讲得云里雾里。其实它的工作方式，你天天见——**快递柜**。

- **Broker（快递柜大爷）**：村口一排柜子，所有人都往这投、都从这取；
- **主题（topic，柜子编号）**：`home/livingroom/temperature`，就是个"编号字符串"，你想投哪个柜、取哪个柜，报编号；
- **发布（publish，投快递）**：板子把温度数据按编号塞进柜子；
- **订阅（subscribe，凭号取件）**：手机认准这个编号，柜子里一有新数据，就归它取。

妙在哪？**投快递的和取快递的，互相不用认识、不用同时在线。** 板子不知道谁在看，手机也不知道数据从哪块板子来，两边只认"柜子编号"。板子离线三天，手机再上线，数据照样取。

这个"谁都不用管谁"的设计，行话叫**发布/订阅**，是物联网能撑起百万设备的根本——设备只管往 Broker 喊，谁来听、听完干啥，设备一概不操心。

## 四、零成本方案：用公共 Broker

搭 Broker 要服务器，新手别急——有个公共测试 Broker：`broker.emqx.io`，全球白用。你的板子往它那喊，你手机订阅同一个主题，立刻通。等以后玩大了，再搭自己的（后面分层篇会讲 EMQ X）。

## 五、代码：复制，改两行，烧录

Arduino IDE 里装两个库：**PubSubClient**（MQTT 用）和 **DHT sensor library**。

```cpp
#include <ESP8266WiFi.h>
#include <PubSubClient.h>
#include <DHT.h>

#define DHTPIN  D4            // DHT11 数据线接 D4
#define DHTTYPE DHT11

const char* ssid        = "你的WiFi名";
const char* password    = "你的WiFi密码";
const char* mqttServer  = "broker.emqx.io";   // 公共 Broker
const int   mqttPort    = 1883;

WiFiClient espClient;
PubSubClient client(espClient);
DHT dht(DHTPIN, DHTTYPE);

void setup() {
  Serial.begin(115200);
  dht.begin();
  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) {   // 等连上 WiFi
    delay(500); Serial.print(".");
  }
  Serial.println("\nWiFi 连上了");
  client.setServer(mqttServer, mqttPort);
}

void loop() {
  if (!client.connected()) reconnect();      // 断了就重连
  client.loop();

  float t = dht.readTemperature();           // 感知：测温
  float h = dht.readHumidity();

  if (!isnan(t)) {
    // 发布：把数据按"编号"塞进快递柜
    client.publish("mylab/temperature", String(t).c_str());
    client.publish("mylab/humidity",    String(h).c_str());
    Serial.printf("已上报：温度 %.1f 湿度 %.1f\n", t, h);
  }
  delay(5000);                               // 5 秒报一次
}

void reconnect() {
  while (!client.connected()) {
    String clientId = "ESP8266-" + String(random(0xffff), HEX);
    if (client.connect(clientId.c_str())) {
      Serial.println("连上 Broker 了");
    } else {
      delay(2000);                           // 没连上，2 秒后再试
    }
  }
}
```

要改的只有两行：`ssid` 和 `password`。

## 六、手机怎么看：订阅同一个编号

手机装个 MQTT 客户端（安卓搜 "MQTT 调试器"之类，iOS 类似），连：

- **服务器**：`broker.emqx.io`，端口 `1883`
- **订阅主题**：`mylab/temperature`

连上后，每 5 秒蹦一个数字——那就是你实验室板子喊上来的温度。

**你躺在宿舍，看见了实验室的温度。** 那个"环"，从实验室出发，经 Broker，到了你眼前。

## 七、翻车点：血泪清单

1. **连不上 WiFi。** ESP8266 **只认 2.4G**，你家路由要是 5G，它直接瞎；
2. **主题两边对不上。** 板子发的是 `mylab/temperature`，手机订阅打成 `mylab/temp`——差一个字母，全盘皆输。主题名逐字符核对；
3. **读数显示 nan。** DHT11 数据线没插好，或者模块坏了，换根线先试试；
4. **公共 Broker 是公共厕所。** 全互联网的人都能往里发消息，所以你的主题名起独特点，比如 `mylab2026/peng/temp`，免得跟别人的数据撞车。

## 八、别高兴太早：环还是断的

现在你能随时看温度了。但老朋友，那个四格咱们再盘一遍：

- 谁看？DHT11 ✓
- 谁想？——**没有**。数据原样上报，没做任何判断；
- 谁做？——**没有**。手机看到 35 度，然后呢？你自己爬起来去开空调；
- 谁回头看？——没有。

发现问题没？**这个系统里，"想"和"做"的活儿，全甩回给你了。** 你成了那个"执行器 + 反馈环"——这不叫智能，这叫"人替系统打工"。

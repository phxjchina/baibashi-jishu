# 中间件：设备世界的"大物业公司"

## 一、我当年的困惑

上篇我说《白话物联网》收官了，结果回评论区一看，追问最多的居然是同一个问题：

**"协议我背下来了， Broker 我也会搭了，可那些大厂的物联网平台，里头到底养着一群什么服务器？"**

这问题问得很狠。因为它戳破了自学最大的幻觉——**会拧螺丝，不等于会造汽车。**

我当年就是这个幻觉的受害者。MQTT 玩得飞起， mosquitto_sub/pub 敲得噼啪响，觉得自己能去做物联网了。直到第一次接真实需求，客户甩过来一句：

"我们要一个平台，能管一万台设备，谁掉线谁知道，能远程升级，能查三个月前的数据，出事能告警，还要给我们现有系统开放接口。"

我当场就懵了：这些词儿单个都懂，合在一起是什么？**一万台设备，难道是一万台 MQTT Client 排队连我的 mosquitto？**

后来我读到付强那本《物联网系统开发：从0到1构建IoT平台》，才算把这块拼图补上。这本书干了一件极其实在的事：**用开源软件，从零搭了一个真能跑的物联网平台，叫 Maque IotHub。** 这本书没跟我谈风月，全是"装 MongoDB、装 EMQ X、写 Node.js"的硬功夫。

这篇就照它讲：**中间件到底是个啥，里面养着哪几种服务器，各自干什么活。**

## 二、中间件是啥？一个"大物业公司"

先给白话定位。你住过小区吧？一个小区里有业主、有住户、有访客，还有自来水公司、电力公司、燃气公司。如果让每户人家自己去跟三家公司扯皮，这日子别过了。

**物业公司，就是小区的"中间件"。**

它对上：替业主跑腿，收快递、修水管、传通知；对下：管理一票基础设施；对外：统一对接水电气。业主不需要懂水泵怎么修，打个电话给物业就行。

物联网中间件，就是设备世界的物业公司：

- **业主** = 你的业务系统（App、网页、大屏、 ERP ）；
- **住户** = 一万台设备（温度计、门禁、摄像头）；
- **水电气公司** = 数据库、消息队列、缓存、 AI 服务。

设备五花八门，说话方式各不相同（有的讲 MQTT，有的讲 CoAP，有的只会 HTTP）；业务系统也各不相同。中间件干的事，就一句话：

> **把一万种不同的设备，包装成对外同一种样子。**

行话管这个叫"屏蔽异构"。白话就是：**让业主只说一句话，物业跑断腿。**

## 三、物业公司的工种表：它到底干什么活

翻开付强那本书， IotHub 的功能清单拉出来是这样的：

| 工种 | 行话 | 白话 |
| --- | --- | --- |
| 户籍科 | 设备生命周期管理 | 谁家的设备？身份证号多少？准不准进小区？ |
| 收发室 | 上行数据处理 | 设备报上来的温度、图片、状态，收进来、存起来 |
| 传达室 | 下行数据处理 | 业务系统的指令，准确送到指定设备手里 |
| 外联部 | Server API | 对外只开这一扇门， RESTful 接口，别人来调用 |
| 特种服务 | 高级功能 | 远程升级（ OTA ）、设备影子、设备分组、 NTP 对时 |

重点说三个最容易被忽略的。

**户籍科（设备生命周期管理）。** 这不是"注册个账号"那么简单。每台设备进小区，物业得给它上户口：它是什么型号、用什么协议、能订阅哪些主题、权限到哪。付强书里的做法是：注册时把设备信息写进 MongoDB，再把允许它访问的主题范围写进 EMQ X 的 ACL （访问控制列表）。以后它想越界偷看别人家的数据？门都没有。

**特种服务里的"设备影子"。** 这个特别妙。设备大部分时间是睡着的（省电），你发指令过去，它装死不应答。怎么办？物业在传达室立个牌子：**设备影子**——设备的"代言人"。指令先贴在影子上，设备醒了来取。业务系统问"那台设备现在什么状态"，物业先看牌子，不用把设备叫醒。

**远程升级（ OTA ）。** 一万台设备散落全国，难道派人一台台刷固件？OTA 就是物业群发升级包：新固件先放服务器，设备上线后自己来取，取完校验、烧写、重启、汇报版本号。哪个没升上去，花名册上一目了然。

你看，这哪是"搭个 Broker"就完事的？**这是一个活色生香的物业公司，一整套编制。**

## 四、物业编制里那几个"服务器"，各是哪路神仙

好，重点来了。付强那本书里，这个物业公司是靠这么几个"编制"撑起来的。我一个一个给你白话翻译：

| 编制 | 大名 | 白话角色 | 看家本领 |
| --- | --- | --- | --- |
| 门房老头 | EMQ X | 收发室 | 专收 MQTT 信，单机号称百万设备 |
| 管家本人 | Node.js | 物业经理 | 业务逻辑全在这，居中调度 |
| 档案柜 | MongoDB | 人事档案室 | 设备信息、用户、配置，灵活存取 |
| 手边抽屉 | Redis | 经理手边的小抽屉 | 热点数据、在线状态，图个快 |
| 内部邮局 | RabbitMQ | 部门之间的邮差 | 异步传信，攒着不丢 |
| 账房先生 | InfluxDB | 记流水账的 | 温度这类时序数据，只增不改 |

挨个说。

**门房老头 EMQ X。** 这是全书的顶梁柱。它是个 MQTT Broker，用 Erlang 语言写的——这语言是瑞典爱立信为电话交换机造的，天生就是为"海量并发长连接"生的。EMQ X 号称单机能扛百万设备连接，靠的不是堆硬件，是 Erlang 那套轻量级进程模型。付强书里还专门讲了它的纵向扩展（单机怎么多接）和横向扩展（多台组成集群，前面挂负载均衡）。

**管家本人 Node.js。** 物业经理是中国人，会所有部门的话。设备说 MQTT 它懂，业务系统说 HTTP 它懂，数据库的方言它也会翻译。付强用 Express 框架把 Server API 搭起来，对外全走 RESTful 风格——这是业界的"普通话"，谁来调用都好使。

**档案柜 MongoDB。** 前面存储那篇讲过，设备的身份信息、配置、阈值，一人一袋，字段灵活，进 MongoDB。

**账房先生 InfluxDB。** 时序数据——设备连接状态变化、温度历史——进 InfluxDB。付强书里拿"蔬菜大棚"举例特别形象：一个大棚是一个 Tag，温度湿度是 Field，时间戳一挂，查"上周每天下午两点的平均温度"飞快。他还把设备上下线的记录也存进去，故障排查时一眼看出"这设备昨天半夜掉了七次线"。

**内部邮局 RabbitMQ。** 这个最容易被新手跳过，但它是真平台和玩具的分水岭。后面 Webhook 那篇专门讲它，这里先埋个钩子。

**手边抽屉 Redis。** 缓存，快就一个字。设备在线状态、实时最新值，放这儿，手机一打开就是热的。

对了，还有个编外人士： **Mosquitto 的命令行客户端**。付强特意说明： Mosquitto 的 Broker 咱不用，只用它的 mosquito_sub/mosquito_pub 这对"对讲机"——测试时喊两嗓子用。可见真平台的每一件工具，都用在刀刃上。

## 五、跟着一台设备，在物业公司里走一遭

光列编制没感觉，跟着一台设备走一遍。这是付强书里 IotHub 的标准流程：

1. **上户口**：厂商在平台注册设备，用户名密码（或证书）写进 MongoDB，主题权限写进 EMQ X ACL；
2. **报到**：设备开机，连上 EMQ X，报告"我是 3 号大棚的温度计，我上线了"；
3. **干活**：设备把温度发布到约定主题；
4. **收信**：EMQ X 收到，通过 Hook 机制通知 Node.js 管家（这是第 25 篇的主角，先记住"Broker 会主动给后端打电话"就行）；
5. **分拣**：管家把数据分三路——身份和配置进 MongoDB、历史温度进 InfluxDB、最新值刷进 Redis；
6. **待命**：业务系统想远程开风机，调 Server API，管家把指令发到 EMQ X，EMQ X 投递给设备；
7. **留痕**：谁上线、谁下线、谁收过什么指令，全记在案。

一台设备的从生到死，全在物业公司的眼皮子底下。**这就是"平台"和"裸 Broker"的差距： Broker 只负责把信送到，平台负责把信读明白、存起来、变服务、还能反悔（下发指令）。**

## 六、一次"差一点翻车"的实训

去年课程实训，有个小组做"教室灯光监控"，前期顺得不可思议，验收前一天崩了。

原因很古典：他们的 Node.js 后端是拿"轮询"从 EMQ X 拿数据的——后端每隔 200 毫秒问一次 Broker："有新消息吗？"演示时设备少，看不出问题。验收前加了五十台模拟设备，后端 CPU 直接打满，像极了那种每隔五分钟给你打一个电话的物业——**你业务还没办，话费先欠费了。**

后来他们照付强的思路，把"轮询"改成"回调"（ Webhook，就是第 25 篇的主角），后端从"打电话问"变成"等电话来"，CPU 立刻掉下去。

这个坑我每年都会带学生踩一遍。因为它的教训太值钱了：**系统与系统之间，"谁主动"这三个字，是架构设计的分水岭。** 主动问，是苦力；被动等，才是设计。

## 七、一点"为什么这么想"的思考

写到这，你发现没有：我们前面十几篇讲的所有技术——感知、网络、 MQTT、数据库——在这个物业公司里，全都有了编制，各就各位。

中间件的本质是什么？我的理解是：**它是"复杂性"的收纳盒。**

一万台设备的千差万别，被它收进一个盒子里，对外只露一个干净的接口。业主（业务系统）不需要知道设备讲的是 MQTT 还是 CoAP，不需要知道数据存在哪，甚至不需要知道设备此刻是死是活——问影子就行。

这就是软件工程里那句老话的肉身：**好的抽象，是让复杂消失在幕后。**

所以我常跟学生说：别迷恋"我搭过 Broker"这种话。搭 Broker 是 Wrestle with technology（跟技术摔跤）；搭平台是 orchestration（ orchestrate， 编一支乐队）——每件乐器都会响不难，难的是让它们在一个节拍上响起。

下一篇，把物业公司用的那套"语言体系"给你理全： MQTT、 CoAP、 LwM2M、 MQTT-SN、 HTTP……一本真书里的**物联网协议大观园**。

# 把那个环闭上：让风扇自己转起来

## 一、这就是那篇"收官"的项目

前面三篇，我们做了门禁、把数据搬上了云。但那个"环"，始终差一口气——

数据上云了，看数据的还是人；判断该不该开空调的，还是人；伸手去按开关的，还是人。

今天把最后半截补上：**让系统自己判断、自己动手、自己再看效果。**

做完这个，你就亲手把一个完整的"反馈控制环"闭合了。这比会接十个模块都值钱。

## 二、材料清单

| 零件 | 干啥用 | 备注 |
| --- | --- | --- |
| Arduino UNO | 大脑 | 用上一篇的 NodeMCU 也行 |
| DHT11 温湿度模块 | 眼睛 | 接着用 |
| 继电器模块 | 大力手 | 单路 5V 继电器，几块钱 |
| 小风扇（或先拿 LED 代替） | 被执行的人 | 验证逻辑用 LED 就够 |

## 三、原理：就是空调那个圈，抄一遍

还记得空调怎么干的吗？看现状、比目标、动手、再看效果、到了就收。

今天这个"智能风扇"，就是把那个圈一字不差地用代码写出来：

```cpp
#include <DHT.h>

#define DHTPIN   2          // DHT11 接 D2
#define DHTTYPE  DHT11
#define FAN_PIN  3          // 风扇（经继电器）接 D3

const float TARGET = 28.0;  // 给定值：目标温度 28 度
const float HYST   = 1.0;   // 回差 1 度，防止反复抽风

DHT dht(DHTPIN, DHTTYPE);
bool fanOn = false;

void setup() {
  pinMode(FAN_PIN, OUTPUT);
  digitalWrite(FAN_PIN, LOW);     // 默认关
  dht.begin();
  Serial.begin(9600);
}

void loop() {
  // 1. 感知：现在几度？
  float t = dht.readTemperature();
  if (isnan(t)) { delay(2000); return; }

  // 2. 决策：比目标，超过就开，降下来就关
  if (!fanOn && t > TARGET) {          // 超了，开
    fanOn = true;
    digitalWrite(FAN_PIN, HIGH);
    Serial.println("超温了，开风扇");
  }
  if (fanOn && t < TARGET - HYST) {    // 降够了，关
    fanOn = false;
    digitalWrite(FAN_PIN, LOW);
    Serial.println("凉了，关风扇");
  }

  // 3. 执行完，等 2 秒再测一次——这就是"再看效果"
  delay(2000);
  Serial.printf("当前 %.1f 度，风扇%s\n", t, fanOn ? "转着" : "停着");
}
```

核心就一个 `if`：**比目标、超了动手、降下来收手、过两秒再看。** 我那个学生说："原来自动化就这么点东西？"——对，就这么点东西，但这就是反馈控制的全部骨架。

## 四、一个必须加的细节：回差

注意代码里那个 `HYST = 1.0`。没有它，你的风扇会"抽风"：

假设目标 28 度，温度在 28 附近抖。超过 28，开；一开，降到 27.9，关；一关，又升到 28.1，又开……风扇一秒开合八次，跟哮喘似的。

解决办法就是回差（hysteresis）：开和关用**两个不同的线**——超过 28 才开，降到 27 以下才关。中间 1 度是"缓冲区"，谁都不动手。空调、冰箱、电热水器，全有这一手，只是人家没告诉你。

## 五、接线与翻车点

继电器三个口：信号脚接 D3，VCC 接 5V，GND 接 GND。风扇电源**别走 Arduino**，继电器只是"开关"，电要从风扇自己的电源来。

翻车点：

1. **继电器吸合了，风扇不转。** 看模块上是标 `HIGH` 吸合还是 `LOW` 吸合——两种都有，买的时候问清楚，代码里的高低电平跟着调；
2. **继电器灯狂闪。** 回差忘了加，回去第四节；
3. **想控 220V 电器。** 打住。强电不是这个玩具继电器的活，交给接触器和电工，别自己拿 USB 小模块瞎试；
4. **风扇有气无力。** 5V 小风扇就这劲，想带劲点换 12V 风扇 + 独立电源。

## 六、进阶：把环接到云上

到这，环已经在本地闭上了。想不想人在宿舍也能改目标温度？

把代码里的 `TARGET` 改成从 MQTT 读：板子订阅 `mylab/target` 这个主题，手机往这个主题发个"26"，板子收到就把目标改成 26 度。

看见没，还是那个快递柜——只不过这回，**数据从"只出不进"变成了"有来有回"**：温度数据出去，控制命令进来。这个环，一头连着真实世界的风扇，一头连着你手机。

到这一步，你可以拍着胸脯说：**我做的不是"会联网的温度计"，是一个能自己看、自己想、自己动手、自己再看效果的物联网系统。**

## 七、一点"为什么这么想"的思考

动手系列四篇走到这，我想你把一个感觉带回去：

物联网的门槛，从来不在"会接多少模块"，而在**你有没有"闭环"这根弦**。同样一块板子，写"测了显示"，它就是温度计；写"测了、比了、干了、再看"，它就是系统。零件一个没多，魂完全不一样。

这就是我反复念叨的系统观——**价值不在零件上，在零件之间的连接和流转上。**

四篇做下来，从门禁到上云到自动控制，你其实已经把前面"是什么"那八篇全亲手验证了一遍。接下来，咱们换个姿势，把环上的每一颗零件掰开揉碎讲：传感器怎么"看"世界，网络怎么选，MQTT 为什么是普通话，中间件那个"指挥"怎么当——分层拆解篇，见。

# 动手做物联网之前，先答应我一件事

## 一、我当年的困惑

每年带学生做物联网课设，我都能见着同一种"翻车现场"。

小伙子揣着开发板回宿舍，熬两个通宵，代码敲得飞起。一周后演示：温湿度、光照、人体感应全接上了，OLED 小屏幕上数字哗哗地跳，还能连手机 App 看曲线。他特得意。

我问一句："那温度高了，它干嘛？"

他想了想："App 上能看啊，我看到了就去开空调。"

我说："那你这两个通宵，做出来一个**会联网的温度计**。"

他当时那个表情，我印象特别深——不是不服，是突然发现哪里不对，但又说不出来哪不对。

今天这篇不开工，先立个规矩。你做完一个"会联网的温度计"，问题不在代码，在你**动手之前少问了一句话**。

## 二、这句话就是：你的"环"呢？

还记得前面几篇反复画的那个圈吗？

> 感知 → 传输 → 决策 → 执行 → **再感知**。

数据从"看世界"出发，走一圈，最后要回到"看世界"上去——这才叫一个系统。

那个小伙子的作品，环断在哪？断在"执行"和"再感知"：数据测了、传了、显示了，但**没有人替它做决定、动手**。看数据的还是人，做决定的还是人，开空调的还是人。系统忙活一圈，最后把活全甩回给了人。

所以我跟你约法一章。以后每动手一个项目，先在纸上画那个环，一格一格填：

1. **谁看？**（用什么感知——传感器还是识别模块）
2. **谁想？**（拿什么判断——单片机上的 if，还是云上的程序）
3. **谁做？**（动什么——舵机、继电器、电机，还是发条消息）
4. **谁回头看效果？**（做完怎么知道做成了）

四格填不满，先别敲代码。**填满了再动手，你的项目才立得住。**

## 三、先做"最小闭环"，别想一口气吃成胖子

填完四格，还有第二条规定：**先做最小闭环，再谈扩展。**

什么叫最小闭环？就是**能跑通、能演示、格子里每样只放最便宜最简单的零件**：

- 感知：一个最土的传感器（甚至一个按钮）就够；
- 传输：先不联网，杜邦线直连；
- 决策：单片机上一个 if 判断；
- 执行：一个 LED 亮灭（代替电机，验证逻辑）。

我见过太多学生一上来就 WiFi、云平台、App 一起上，结果连环境配一周，环还没闭。何必呢？**最小闭环的价值，是让你先用最便宜的成本，把"系统能转"这件事验证了。** 环转起来了，再往上加功能——那是装修；环转不起来，堆再多也是毛坯。

拿 LED 当"假执行器"，这个技巧我年年教：逻辑通了，把 LED 换成风扇，代码改一行就完事。

## 四、一个反面教材的"抢救"过程

有个小组做"智能储物柜"，刷校园卡取件。他们一头扎进 App 和数据库，做了三周，储物柜本身只能开不能关，卡复制的漏洞也没堵。演示当天，柜门弹开就再也关不上了。

我让他们停下来，重新画环。画完他们自己发现：他们做的全是"云端那半截"（账号、记录、App），**柜子本地那个环（刷卡→验证→开门→关门→确认关好）根本没做**。这就是没画环就动手的典型：热闹的全做了，保命的没人做。

后来他们砍掉 App，先用 RC522 + 舵机 + 门磁，把"刷卡开、定时关、门磁确认关好"这个本地小环跑通，半天搞定。再往上接网络，顺理成章。

**先闭小环，再扩大连。顺序反了，全白干。**

## 五、后面的路，我给你排好了

规矩立完了，后面四步，咱们一步步真刀真枪地干：

1. **门禁**：Arduino + RC522，刷卡识别、舵机开门——先闭一个"识别→动作"的最小环；
2. **上云**：ESP8266 + MQTT，把温度送上云，手机随时看——给环装上"神经"；
3. **闭环**：温控风扇，让系统自己看温度、自己决定、自己开风扇、自己再看效果——把那个环彻底闭上；
4. 每一步，都只加一样新东西，但每一步，环都是**闭合**的。

## 六、一点"为什么这么想"的思考

这个"先画环再动手"，表面看是个工程习惯，骨子里是我一直强调的**系统观落地**。

人天生爱盯着零件使劲：模块买贵的、代码抄现成的、界面做炫的——因为零件看得见，有成就感。而"连接"和"闭环"看不见，所以最容易被跳过。可系统的价值，恰恰长在看不见的地方。

你答应我这一件事——动手前先画环——其实就是逼自己从"攒零件"切换到"搭系统"。这一个切换，比你学会任何一个模块都值钱。

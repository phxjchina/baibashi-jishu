# 把大仓库拆成很多小库：HDFS

上篇说 Hadoop 是座'工厂'，这座工厂有两大车间：一个管存，一个管算。先看管存的——**HDFS**，全称 Hadoop Distributed File System，翻译过来是'Hadoop 分布式文件系统'。

名字照样唬人。拆开看：**文件系统**就是管文件怎么存的（你电脑里的 C 盘、D 盘，背后也是文件系统在管）；**分布式**，就是'不在一台机器上存，分散到一群机器上存'。

## 一个文件，切成很多块

💡 一个电影文件 4 个 GB，一台机器存得下，干嘛要拆？

因为要存的东西不止一部电影——是全互联网的数据。单个文件可能大到一个硬盘装不下，更关键的是：**一个文件只存在一台机器上，这台机器一坏，文件就没了**。

HDFS 的办法是'切块 + 复印'：

1. **切**：把一个大文件按固定大小（默认 128 MB）切成一块一块的，像把一列长火车拆成车厢；
2. **散**：这些'车厢'分散存到集群里的多台机器上，每台机器只管几块；
3. **复印**：每一块都不只存一份，默认存三份——这叫**多副本**。任何一台机器坏了，数据在别处还有备份，照拿不误。

## 它和图書館有啥像

💡 你可以把 HDFS 想成一个'智能图书馆系统'：

- 一部 100 册的丛书，不锁在一个书架上，而是拆开放在三个分馆——（切块 + 分散）
- 每册书复印三本，分放三处——（多副本）
- 你想借第 37 册，系统告诉你：3 号馆有货。（元数据管理）

HDFS 里有个'总管理员'（NameNode），专门记一本总账：哪个块存在哪台机器上、各存了几份。其他机器（DataNode）就是'分馆'，只负责埋头存块、按指令交块。

📌 **技术内涵**：HDFS 是运行在廉价硬件集群上的分布式文件系统，设计目标是**高容错、高吞吐**：通过数据分块（block）+ 多副本（默认 3 副本）+ 机架感知的副本放置策略保证可靠性；适合'一次写、多次读'的大文件场景（比如日志、视频），不适合大量小文件和高频随机修改。NameNode 管元数据、DataNode 管实际数据，是典型的主从架构。

## 它的脾气

HDFS 有两条鲜明的'性格'，用它的地方得顺着来：

- **擅长干粗活**：大文件、批量读、顺序读，效率极高；
- **不擅长干细活**：存几百万个小文件、频繁改文件内容、要求毫秒级响应——这些它干不来，得请别的系统（比如后面讲的对象存储）。

💡 打个比方：HDFS 像运河货轮，运大件、跑长途，一船拉一万吨；你要送个加急快递件，得换顺丰——不同工具干不同的活。

## 一句话记住

> HDFS：大文件切块散存一群机器，每块复印三份防丢——便宜机器也能凑出靠谱大海量存储。

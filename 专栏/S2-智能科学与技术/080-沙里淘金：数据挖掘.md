# 沙里淘金：数据挖掘

存有 Hadoop、算有 Spark，工具箱算齐了。可这些工具到底图啥？答案是：**从沙子里淘金**。

这座'沙子'，就是堆在仓库里的海量数据；那把'金子'，是藏在数据里的规律。**数据挖掘**，就是从大量数据中找出隐含的、有用的规律和知识的过程。

## 一个真实发生过的传说

💡 零售业有个流传很广的故事：某超市分析购物小票，发现**周五傍晚，买尿布的顾客里相当一部分会顺手买啤酒**。看着八竿子打不着，数据摆在那儿。超市后来把啤酒和尿布的货架摆到一块——两个品类的销量都涨了。

这个故事真假有争议，但它把数据挖掘的形态讲活了：**规律就在那里，只是没人看得到，直到机器把几百万张小票摊开一起看**。

## 淘金的几种'筛子'

数据挖掘的常用招法，按你想淘什么金分几类：

| 想淘的金 | 招法 | 大白话 |
|---|---|---|
| 谁和谁是一类 | **聚类** | 把相似的人/东西分堆 |
| 这事该归哪类 | **分类** | 判断邮件是不是垃圾邮件 |
| 接下来会怎样 | **预测** | 预测客户下个月会不会流失 |
| 啥和啥总一起出现 | **关联规则** | 买 A 的人常买 B（啤酒尿布） |
| 谁跟谁不一样 | **异常检测** | 信用卡突然在境外狂刷，抓！ |

眼尖的同学看出来了：这些招法——聚类、分类、预测——正是系列三、系列四讲过的机器学习套路。没错，**数据挖掘和机器学习是一体两面**：机器学习提供算法，数据挖掘提供战场。

📌 **技术内涵**：数据挖掘（Data Mining）是数据库、统计学、机器学习与模式识别的交叉领域，标准流程常称 **CRISP-DM**：业务理解 → 数据理解 → 数据准备 → 建模 → 评估 → 部署。它的产出不是'更干净的数据'，而是**可行动的洞察**（actionable insight）——能直接指导决策的规律。挖得准不准，一半靠算法，一半靠对业务的理解。

## 从哪儿下手：一半科学一半手艺

💡 数据挖掘不是'把数据倒进机器就出金子'，它有个朴素的工作流：

1. **想清楚要回答什么问题**——'哪些客户要流失'比'挖点啥'强一万倍；
2. **准备数据**——清洗、整理（脏数据占九成是大数据圈的日常吐槽）；
3. **选招法建模**——上表那几样挑合适的；
4. **验证**——规律在历史数据上灵，换批新数据还灵不灵；
5. **用起来**——把规律嵌进业务流程，才算出真淘到了金。

## 一句话记住

> 数据挖掘：不生产新数据，只是数据的'侦探'——从堆积如山的记录里，把'看不见但有用'的规律翻出来。
